```
endfield-player/
├── src/                     # Web 源码

```

## 构建 Android APK

需要 JDK 17+（推荐 21）、Android SDK（platform 36 / build-tools 36）、Gradle 8.14+。

```bash
# 1. 构建 Web 产物（专用配置，产出 dist/apk）
npx vite build --config vite.capacitor.config.ts

# 2. 同步到 Android 工程
npx cap sync android

# 3. 构建 debug APK（产物在 android/app/build/outputs/apk/debug/）
cd android
gradle assembleDebug
```

## 一键构建脚本（本机）

```powershell
pwsh tools/build-apk.ps1                  # 完整版（要求 public/songs 内有歌曲资产）
pwsh tools/build-apk.ps1 -NoSongs         # 无歌曲版（R8 压缩后约 2 MB，无预置曲库）
pwsh tools/build-apk.ps1 -Type both -OutDir D:\out

# 重新生成应用图标（改 design 参数后覆写 res/mipmap-* 与 public/favicon.png）
python tools/make-icon.py --out <输出目录> --variant eq
```

### 版本号规则

- 版本号取自 `package.json` 的 `version`，`versionCode` 自动推导为 `主 × 10000 + 次 × 100 + 修`（`1.4.3` → `10403`），也可用 `-PappVersionName=` / `-PappVersionCode=` 覆盖
- Gradle 手工覆盖示例：`./gradlew assembleRelease -PappVersionName=1.4.3 -PappVersionCode=10403`
- 预置曲库索引 `public/songs/manifest.json` **不入库**，由 `node tools/gen-song-manifest.mjs` 从本地歌曲资产生成（歌曲资产见 Release 资产包 `EndfieldSongs-v1.0.zip`）
- `-NoSongs`（无歌曲版）：v1.4.3 起改为**构建期排除**——脚本设置 `ENDFIELD_LITE=1`，由 `vite.capacitor.config.ts`（`copyPublicDir = false` + 只复制 `public/` 中非 `songs/` 部分的插件）实现，并清理 Android assets 里的旧 `songs` 目录；**不再移动源目录**，构建中断或并发都不会弄丢歌曲资产
- 历史做法（v1.4.3 之前）：`-NoSongs` 会先把 `public/songs` 临时移开再构建
- 产物默认输出到仓库同级目录 `apk-out/`（可用 `-OutDir` 指定），文件名形如 `EndfieldMusicTerminal-v1.4.3-release-lite.apk` / `...-full.apk`，构建日志会给出体积与 SHA256
- 脚本通过 `-ToolsRoot <dir>` 或环境变量 `ENDFIELD_TOOLS` 定位 JDK 21 / Android SDK / Gradle 8.14.3 工具链

## 测试

### 前端单元测试（vitest）

- 运行：`npm test`（即 `vitest run`）
- 配置：`vitest.config.ts` —— `environment: 'node'`、`include: ['src/**/*.test.ts']`，只测纯逻辑，不需要 DOM
- 用例：`src/lib/` 下的 `lyrics.test.ts`、`music.test.ts`、`playlists.test.ts`、`search.test.ts`、`stream.test.ts`、`playlist-file.test.ts`、`radio-browser.test.ts`（原 README 记录的「前端 50 项」是 v1.4.3 时的规模，用例随功能持续增加；全部已接入 CI）

### 原生单元测试（Java）

- 用例：`android/app/src/test/java/com/endfield/audio/terminal/lyrics/LyricsParsingTest.java`（原生歌词解析 8 项）
- 本机运行：`pwsh tools/run-java-tests.ps1`（用 `javac` + JUnit 4 直接编译运行，不需要 Android SDK；JUnit / hamcrest / org.json 取自本地 Gradle 缓存）
- 之所以不用 AGP：本机项目路径含非 ASCII 字符时 `:app:testDebugUnitTest` 无法加载测试类；CI 中改为从 Maven Central 下载同样的三个 jar，再走同一套 `javac` + `JUnitCore` 流程

### 静态检查

- `npm run typecheck`（`tsc -p tsconfig.app.json`）与 `npm run lint:eslint`（`eslint src`），`npm run lint` 会并发执行两者；CI 每次 push 都会先跑这两项

## CI 与发布流程

### GitHub Actions 自动构建

每次 push 到 `main` 会先做类型检查与 ESLint 检查，再自动构建 debug APK，产物上传为 Actions Artifact（仓库 Actions 页面可下载最新版）。

如需自动构建**正式签名版**，在仓库 Settings → Secrets and variables → Actions 新增：

| Secret | 值 |
| --- | --- |
| `KEYSTORE_BASE64` | 密钥库文件 base64 编码（`base64 -w0 release.keystore` 或 `certutil -encode` 输出） |
| `KEYSTORE_PASSWORD` | 密钥库密码（storePassword = keyPassword） |
| `KEYSTORE_ALIAS` | 密钥别名（本项目为 `endfield`） |

配置后，每次 push 的 `release` job 会自动用该密钥构建并上传正式签名 APK。

### 打标签自动发版

推送形如 `v1.4.3` 的标签（或在 Actions 页面手动运行 `Release` 工作流并填标签）会依次执行：类型检查与 ESLint → 用 secrets 还原签名密钥 → 构建签名 APK（版本号取自标签）→ 创建或更新对应 Release，并上传 `EndfieldMusicTerminal-v1.4.3.apk`。

### 工作流文件

| 文件 | 作用 |
| --- | --- |
| `.github/workflows/build-apk.yml` | push 到 `main`：类型检查 / ESLint / vitest → Java 单测 → 构建 debug APK 上传 Artifact；配置了签名 secrets 时再构建并上传 release APK |
| `.github/workflows/release.yml` | 推送 `v*` 标签（或手动填标签）：用 secrets 还原密钥、`-PappVersionName=<标签>` 构建签名 APK，并用 `gh release` 创建或更新对应 Release |
| `.github/dependabot.yml` | 依赖更新机器人 |
| `.github/ISSUE_TEMPLATE/`、`.github/PULL_REQUEST_TEMPLATE.md` | Issue / PR 模板 |

> 注：仓库不携带预置歌曲（歌曲资产在 `EndfieldSongs-v1.0.zip` 里），因此 CI 构建出来的是**无歌曲版（lite）** APK。

## 应用图标生成

- 图标由 `tools/make-icon.py` **程序化生成**，可复现、可微调（`--variant eq` / `--variant play`），输出主图、自适应图标背景层与 66% 安全区前景层、亮 / 暗预览：

```powershell
python tools/make-icon.py --out <输出目录> --variant eq
```

- 仓库内的图标资产：`docs/icon/icon.svg`、`docs/icon/icon-1024.png`
